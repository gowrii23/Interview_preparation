# Interview Q&A: topological order and union-find

## Q1. How do you decide between union-find and a topological sort in the first thirty seconds?

**Answer:** I look at the edge meaning. If the edge is undirected — "these two nodes are connected," "this cable joins two computers" — I want components, cycles-as-redundancy, or a tree test, and I use union-find. If the edge is directed — "this course precedes that one," "this letter comes before that letter" — I want an order or a directed cycle, and I use Kahn or DFS colors. A question can wear a disguise. "Is this undirected graph a tree?" mentions no order, so the n, n−1, one-component test is union-find. "Is there a cycle?" on a directed graph is topological. "Is there a cycle?" on an undirected graph is the redundant-union test, not Kahn. Picking Kahn for an undirected graph forces me to orient edges arbitrarily and then "find a cycle" that may just be the two directions of one undirected edge.

## Q2. What do path compression and union by rank each buy you?

**Answer:** Path compression points a node at its grandparent, or directly at the root, during `find`, so the next lookup skips the chain. Union by rank refuses to attach a taller tree under a shorter one, so the uncompressed height stays logarithmic. Together, a sequence of m operations on n nodes is O(m α(n)), and α(n) is at most 4 for any structure that fits in memory. Either optimization alone is enough to make the structure fast in interviews; both is the version I write. Skipping both leaves a correct algorithm that can degenerate into a linked list and O(n) per find. I would rather write the ten extra lines than defend a worst-case chain. Rank is not the number of nodes in the tree. I do not use it as a component size unless I stored size on purpose.

## Q3. Why is "n nodes and n−1 edges" not enough to prove a tree?

**Answer:** A tree on n nodes is connected and acyclic, and those two properties force exactly n−1 edges. The converse needs one more check. n−1 edges can include a triangle on three nodes and an isolated fourth node: the count matches, and the graph is neither connected nor acyclic. n−1 edges plus "every union linked two different roots" implies both connectedness and no cycle, because each successful union reduces the component count by 1 and you started at n, so you finish at 1. n−1 edges plus a final component count of 1 is the same test. I say both conditions out loud. A single successful-looking edge count, or a component count without looking at extra edges, accepts either a disconnected graph or a unicyclic connected graph.

## Q4. Kahn's algorithm stopped with nodes left over. What do you return, and what do those nodes look like?

**Answer:** I return "no topological order." For alien dictionary that is the empty string. For course schedule II it is an empty list. For the boolean course schedule it is false. I do not return the prefix of nodes I already peeled. Those were schedulable, and the caller asked for an order of everyone. The leftovers each have indegree greater than 0, and their only remaining incoming edges come from other leftovers, so they sit on one or more cycles. A self-loop is the smallest picture: one node, indegree 1, empty frontier, empty order. I also treat a back edge found by DFS the same way. Gray means "this node is already on the path I am building," so I abort the whole order rather than skip the edge.

## Q5. How do you avoid counting the same directed precedence twice?

**Answer:** Several adjacent word pairs, or several prerequisite rows, can describe the same logical edge. If I increment indegree every time I see it and I only store the edge once, Kahn decrements once and the extra count never returns to zero, so a DAG looks cyclic. If I both increment twice and store the edge twice, the numbers happen to match and the order is still right, at the cost of extra list entries. The clean version remembers whether the edge exists — a boolean matrix for a 26-letter alphabet, a set of pairs otherwise — and touches indegree only on the first insertion. Undirected union-find has the matching issue in a milder form: a repeated undirected edge must not decrement the component count. `union` returning false is that guard.

## Q6. What complexity do you quote, and where do people hide an extra V factor?

**Answer:** Union-find over E edges is O(E α(n)) time and O(n) space. Topological sort is O(V + E) time and space. I include building the adjacency list in that bound. The hidden factor is a `find` that scans all nodes to see who shares a root, which turns each union into O(n) and the whole algorithm into O(nE), or a topological check that sorts the adjacency matrix from scratch after every edge. Another one is rebuilding the set of indegree-zero nodes by scanning all V nodes after every pop instead of pushing a node at the moment its indegree hits zero. That is O(V² + E). The queue is what keeps Kahn linear. I mention α(n) only if the interviewer asks why union-find is not plainly O(E log n). Otherwise "nearly constant per operation, overall linear in the edges" is the right sentence, followed by the precise bound if they want it.
