# Interview preparation

Notes for four interview tracks. Every topic has its own Markdown file. Teaching notes (`*-study.md`) are separate from sample questions and answers (`*-interview-qa.md`). Diagrams are mermaid; dotted arrows mark async work, caches, frozen weights, pruned branches, or optional paths.

## Tracks

1. [SDE and principal architect](01-sde-principal-architect/README.md) — Java, Spring, React, Kubernetes, Kafka, RabbitMQ, Oracle, PostgreSQL, Redis, Cassandra, AWS, and principal-level design.
2. [ML, LLMs, and agentic AI](02-ml-ai/README.md) — foundations, LoRA, QLoRA, evaluation, RAG, MCP, agents, Indic-language interviews, and a project story bank.
3. [Remote AI training and annotation](03-remote-data-annotation/README.md) — Mercor, Alignerr, preference labeling, code review tasks, and rubrics.
4. [NeetCode 75](04-dsa-neetcode-75/README.md) — the Blind 75 set, each problem in Java and Python with an analogy and a walkthrough.

## How to use this

- For a principal loop, start with the POS system-design note and the principal-craft note, then drill the stack you are weakest in. React is written for a backend lead who can read UI code, not for a specialist frontend role.
- For an AIML loop, do LoRA and QLoRA until you can derive the parameter count and the memory story on a whiteboard, then the agent and MCP notes tied to the defect-triage project.
- For Mercor or Alignerr, practice the code-evaluation and rubric notes out loud. Follow the guideline in the task, and do not treat fluency as correctness.
- For DSA, one pattern folder per sitting. Write the Java solution, then the Python solution, without looking.

Problem statements in the DSA notes are paraphrased. LeetCode links are included so you can submit on the judge.
